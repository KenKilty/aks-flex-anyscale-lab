Before you submit the workload, confirm that every part of its path is healthy.
You will check the CPU scale profile, Cilium service routing, Flex DNS, and the
Anyscale Gateway API path without starting a Ray job.

## What You Will Do

You will set quota-safe bounds for the home-region CPU node pool and separate
that autoscaling behavior from the fixed Flex host capacity. Then you will rerun
the Cilium, DNS, HTTPS egress, and Anyscale Gateway checks so the workload starts
from a healthy cluster state. If you enabled the GPU path, you will also confirm
that the Flex host exposes allocatable `nvidia.com/gpu`.

## Understanding the capacity model

Your environment has two distinct compute locations:

| Location | Managed by | Scales how |
| ---------- | ----------- | ------------ |
| Region A AKS CPU pool (`cpu`) | AKS cluster autoscaler | Adds nodes from Azure capacity on demand |
| Region B Flex host | You provisioned and joined it to AKS | Fixed capacity, already `Ready` |

The Flex host does **not** autoscale. It is pre-provisioned and permanently
joined. Anyscale can place workers on it immediately without waiting for a scale event.

:::warning Flex capacity remains allocated
The AKS CPU pool can scale within its configured bounds. The Flex VM stays
allocated until you remove the environment in Module 7, even when no worker pod
is running.
:::

## Step 1: Review the AKS CPU pool

```bash
source .env
RG="rg-${TF_VAR_project}-${TF_VAR_environment}-${TF_VAR_region_short}"
CLUSTER="aks-${TF_VAR_project}-${TF_VAR_environment}-${TF_VAR_region_short}"

az aks nodepool list \
  --resource-group "$RG" \
  --cluster-name "$CLUSTER" \
  --query '[].{Name:name,VmSize:vmSize,Count:count,MinCount:minCount,MaxCount:maxCount,Mode:mode}' \
  -o table
```

Expected output:

```text
Name    VmSize            Count    MinCount    MaxCount    Mode
------  ----------------  -------  ----------  ----------  ------
sys     Standard_D4s_v5   1        1           3           System
cpu     Standard_D16s_v5  1        1           4           User
```

## Step 2: Review the CPU or GPU capacity profile

### CPU path

```bash
grep -E '^(TF_VAR_cpu_vm_size|TF_VAR_gpu_pool_configs)=' .env
```

Expected output:

```text
TF_VAR_cpu_vm_size="Standard_D16s_v5"
TF_VAR_gpu_pool_configs='{}'
```

Terraform keeps one CPU node ready and can scale the pool to four nodes. The
`Standard_D16s_v5` node provides the resources required by the Ray head. Your
quota check reserved 20 DSv5 cores for this CPU node plus the system node.

### GPU driver and device plugin

Choose the GPU path before provisioning the Flex host. If you are continuing
from a CPU-only host, changing the Flex VM size or image will replace that host.
Start with a new environment when you want to switch paths without replacing an
existing VM.

Review the GPU values you selected in Module 1:

```bash
grep -E '^(TF_VAR_flex_host_vm_size|TF_VAR_flex_host_source_image_reference|ANYSCALE_FLEX_GPU_ENABLED|ANYSCALE_RESULTS_GPU_)=' .env
```

Enable this path only after you confirm quota and capacity for the selected GPU
VM size in the Flex region. GPU workers must run on the Flex node. If they land
on an AKS managed GPU node pool, the placement is incorrect.

## Step 3: Apply the capacity settings

```bash
./scripts/anyscale-aks.sh apply
```

For the CPU path, this confirms that the Anyscale resources and fixed CPU
autoscaling bounds have converged. If you changed the Flex host VM size or image
for the GPU path, Terraform will replace the Flex host so the new GPU-capable
image can boot.

Expected output:

```text
Apply complete! Resources: 0 added, 0 changed, 0 destroyed.
```

## Step 4: Check that the workload path is ready

### GPU path

Skip this subsection for the CPU path. If you enabled the GPU path, first confirm
the Flex host driver and then install the NVIDIA device plugin before running the
shared readiness checks. The installation script targets the Flex node and adds
the required taint tolerations.

```bash
ssh -i "$SSH_PRIVATE_KEY_PATH" \
  "${TF_VAR_flex_host_admin_username}@$(./scripts/anyscale-aks.sh output -raw flex_host_public_ip)" \
  'nvidia-smi --query-gpu=name,driver_version --format=csv,noheader'
```

Expected output:

```text
<gpu-name>, <driver-version>
```

The installation script labels the Flex node with
`nvidia.com/gpu.product` from `ANYSCALE_RESULTS_GPU_PRODUCT_LABEL`, matching the
accelerator selected for the Anyscale GPU worker.

```bash
./scripts/install-nvidia-device-plugin.sh
```

Expected output:

```text
daemonset.apps/nvidia-device-plugin-daemonset configured
daemon set "nvidia-device-plugin-daemonset" successfully rolled out
NVIDIA device plugin ready: 1 allocatable GPU(s) in pool aksflexnodes
```

### CPU and GPU paths

Run the readiness checks for the CPU scale profile, selected GPU settings, Cilium,
the Flex node, DNS, HTTPS access, traffic between AKS and Flex pods, and the
Anyscale extension and Gateway:

```bash
./scripts/validate-lab.sh m5
```

Expected output:

```text
PASS M5-01 CPU node pool autoscaling configured
SKIP M5-02 GPU path disabled in current env profile
PASS Unmanaged upstream Cilium cluster-pool IPAM and VXLAN ready
PASS Flex node <flex-node-name> Ready in <region-b>
PASS Cilium agent and Envoy Ready on Flex node <flex-node-name>
PASS Flex ClusterFirst DNS resolves Anyscale and Kubernetes service names
PASS Flex pod HTTPS egress reaches console.azure.anyscale.com
PASS Upstream Cilium connectivity: AKS and Flex pods exchanged traffic and AKS reached Flex ClusterIP <service-ip>:8080
PASS Anyscale extension and operator pods ready
PASS Gateway anyscale-operator/anyscale-gateway programmed at 20.190.18.76
```

The command writes pod logs and Kubernetes JSON under
`.cache/lab-validation/m5-flex-network/`. If a check fails, use that directory first;
it contains the short-lived diagnostic pod output before cleanup.

## Step 5: Inspect Anyscale service health

The readiness command already checked these resources. Use the following commands
when you want to inspect the extension and Gateway directly.

```bash
source .env
RG="rg-${TF_VAR_project}-${TF_VAR_environment}-${TF_VAR_region_short}"
CLUSTER="aks-${TF_VAR_project}-${TF_VAR_environment}-${TF_VAR_region_short}"

az k8s-extension show \
  --cluster-name "$CLUSTER" \
  --resource-group "$RG" \
  --cluster-type managedClusters \
  --name anyscale-operator \
  --query '{name:name,provisioningState:provisioningState,currentVersion:currentVersion}' -o json

kubectl get pods,gateway -n anyscale-operator -o wide
```

Expected output:

```text
{
  "name": "anyscale-operator",
  "provisioningState": "Succeeded",
  "currentVersion": "1.7.1"
}

pod/anyscale-operator-556c4df7cb-tq4r7   3/3   Running
gateway.gateway.networking.k8s.io/anyscale-gateway   istio   20.190.18.76   True
```

:::warning Resolve failed checks before continuing
Do not submit the workload if any check above fails. Ray services need healthy
Cilium routing, ClusterFirst DNS, and an available Anyscale Gateway.
:::

## Step 6: Verify the Flex node has only system pods

```bash
source .env
FLEX_NODE="vm-flex-${TF_VAR_project}-${TF_VAR_environment}-${TF_VAR_flex_region_short}"
kubectl get pods -A -o wide --field-selector spec.nodeName="$FLEX_NODE"
```

Expected output:

```text
NAMESPACE     NAME                    READY   STATUS    NODE
kube-system   cilium-abcde            1/1     Running   <flex-node-name>
kube-system   cilium-envoy-abcde      1/1     Running   <flex-node-name>
```

Only the Cilium and Cilium Envoy system pods should appear before you submit the
workload. Any application pod on this node is leftover from an earlier run and
should finish or be removed before you continue.

## Results to keep

You can move on when `./scripts/validate-lab.sh m5` prints `PASS` for the
CPU scale profile, Flex node readiness, Flex DNS, Flex HTTPS egress, AKS-to-Flex
pod reachability, and Anyscale Gateway health. If the GPU path is enabled, the
same command should also report allocatable `nvidia.com/gpu` on `aksflexnodes`.
